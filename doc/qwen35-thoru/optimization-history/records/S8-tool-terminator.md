# S8 — 单工具请求在闭合标记处停止生成

触发条件是请求明确设置 `parallel_tool_calls=false`，且传入了工具定义。对于能将 `</tool_call>` 编码为一个可往返还原 token 的模型，将该 token 加入本次 generation 的 EOS 集合，但保留在流式与最终文本中，供工具解析器完成结构化调用。

Qwen3.6-35B-A3B 当前 tokenizer 的闭合 token 为 248059（从模型文件核对，不在代码中硬编码）。MTP 使用原有 EOS/partial-acceptance 事务提交到终止位置；不依赖文本 callback 强行取消一个已部分提交的 speculative round。其他 tokenizer 无法满足单 token 往返检查时保留原有生成路径。

AIOS 代理通过可选 `--single-tool-call` 发送该请求设置。它限制每次模型响应最多一个工具调用，不限制整个 Agent 任务只能进行一次工具查询。最终文字之后的第一个错误工具调用仍属于工具选择问题，不能据此宣称所有异常都已解决。

验证：Serving CPU 测试 22 项通过（lib 5、Anthropic 4、OpenAI 13），包括显式单工具标志传递、默认并行行为、工具闭合后的流解析和错误流处理；天气计时工具 CPU 测试 9 项通过。CUDA构建及真实天气10轮测试已完成，记录如下。

对照背景：未加早停的 `9d6642c5` 新一批正式 10 轮严格通过 8 轮；完整记录保留成功与失败，不将成功子集的中位数冒充总体有效成绩。新增早停版本正式10/10通过，中位数1.775060 s、P90 2.058380 s。两组行为与调用次数有变化，不从失败总体计算固定加速比。
